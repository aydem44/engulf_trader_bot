# AGENTS.md — Нерушимые правила Проекта

## 1. Контекст и навигация
- Рабочий каталог: `/home/study/projects/trading/engulf_trader_bot`.
- Стек: Python 3.12+ (`.python-version`, `.venv`), управление зависимостями через `uv`.
- Фактические библиотеки кода: `pybit` (`pybit.unified_trading.HTTP`), `pandas`, `numpy`, `python-dotenv`, `requests`; стандартные `csv`, `decimal`, `logging`.
- pyproject.toml пока не настроен, зависимости устанавливаются вручную или через uv add.
- Точка входа: `engulf_trader_bot.py`; параметры — `config.py`; сигналы — `strategy.py`; исполнение — `trader.py`.
- Карта архитектуры, границ слоёв и зон риска: `architecture-map.md` в корне проекта (`/home/study/projects/trading/engulf_trader_bot/architecture-map.md`).
- Перед началом любой задачи сверяйся с `architecture-map.md` и проверяй наличие подходящего процедурного скила в `.agents/skills/` (в текущей версии проекта этот каталог отсутствует).

## 2. Нерушимые правила архитектуры и границ слоёв

1. **Слой интеграции (Data Provider):** `fetch_klines()`.
   - Задача: только получение данных с Bybit.
   - ЗАПРЕЩЕНО: содержать бизнес-логику или расчет индикаторов.
2. **Доменный слой (Стратегия):** `strategy.py`.
   - Задача: чистая логика сигналов (вход/выход).
   - СТРОГИЙ ЗАПРЕТ: импортировать `pybit`, вызывать API, отправлять ордера, писать в CSV.
3. **Слой исполнения (Трейдер):** `trader.py`.
   - Задача: отправка ордеров, логирование в CSV, уведомления в Telegram.
   - СТРОГИЙ ЗАПРЕТ: принимать решения о входе/выходе (это делает стратегия).
4. **Оркестратор:** `engulf_trader_bot.py` (главный цикл).
   - Задача: связать слои (вызвать fetch -> strategy -> trader).
   - СТРОГИЙ ЗАПРЕТ: содержать бизнес-логику или прямые вызовы API, кроме координации.

## 4. Строгие запреты против обхода проверок (Anti-Cheat) и безопасность
КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО:
- ослаблять или удалять существующие `assert` в тестах ради «озеленения» прогона;
- добавлять `# type: ignore`, `# pyright: ignore` или `# noqa` без письменного разрешения руководителя проекта;
- глушить исключения конструкциями `except Exception: pass`;
- снижать значение `fail_under` в секции `[tool.coverage.report]` файла `pyproject.toml` (действует правило только вверх: порог покрытия тестами можно только повышать, но нельзя снижать);
- менять рабочий код сервиса до того, как снят защитный слепок поведения сервиса до правок (Characterization Tests);
- коммитить код без указания источника: все коммиты обязаны содержать префикс `[agent]` (автономный коммит агента под скилом), `[assisted]` (коммит разработчика с ручной доработкой предложения агента) или `[manual]` (ручной коммит разработчика) для аудита соответствия и метрик зрелости процессов (AI Compliance & Fluency);
- автоматически вливать (auto-merge) ветки и Pull Request без явного ревью и одобрения человеком-разработчиком (Human-in-the-Loop).


## 5. Жесткие ворота готовности (Definition of Done)

В проекте нет тестов и тестового режима; `pytest`, `ruff` и `basedpyright` не настроены в `pyproject.toml`. Запускать `main()` для проверки нельзя — он торгует реальными деньгами. Задача считается выполненной, когда все команды ниже завершились с кодом возврата `0`:
1. `uv run python -m py_compile engulf_trader_bot.py strategy.py trader.py config.py`
2. `git diff --check`
3. `uv lock --check`

Дополнительно вручную проверяется:
- изменения не нарушают границы слоёв из `architecture-map.md`;
- в диффе не добавлено новых прямых вызовов Bybit в `main()` и новой бизнес-логики в `fetch_klines()`;
- при изменении позиции проверены `retCode`, пустой `list`, `size > 0` и подтверждение закрытия по `size == 0`.

## 6. Использование процедурных скилов
1. Для каждой задачи найди подходящий скил в `.agents/skills/<имя-скила>/SKILL.md` и выполняй его фазы строго по порядку.
2. Не завершай работу, пока не закрыты все пункты Definition of Done активированного скила.
3. Если сработало стоп-условие скила — остановись, откати изменения и доложи человеку, а не обходи запрет.
