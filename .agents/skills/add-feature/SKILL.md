# Скилл: Разработка новой фичи (add-feature)

## 1. Назначение и триггеры

- **Применять когда:** Нужно добавить новый фильтр, индикатор, проверку баланса или изменить существующую логику без исправления багов.
- **НЕ применять:** Для исправления ошибок (используй `fix-position-state`) или для перестройки слоев (используй `refactor-architecture`).

## 2. Предусловия (Inputs)

- Репозиторий проекта развернут в `~/projects/trading/engulf_trader_bot`.
- Рабочая ветка чиста (`git status --short` пуст).
- Все текущие тесты проходят (`uv run pytest`).
- `architecture-map.md` существует и актуален.

## 3. Пошаговая процедура (Execution Steps)

### Фаза 1: Планирование (Read-Only)
1. Прочитай `architecture-map.md` и определи, в какой слой относится новая фича (Стратегия, Исполнение, Оркестратор).
2. Определи зону влияния правок (разрешённые и запрещённые файлы).
3. Напиши **красный тест** (в `tests/`) на новую функциональность. Запусти `pytest` и убедись, что он падает по ожидаемой причине.

### Фаза 2: Реализация (снизу вверх)
1. **Доменный слой (`strategy.py`):** Если фича меняет логику сигнала — добавь её сюда. Не добавляй сюда API-вызовы.
2. **Слой исполнения (`trader.py`):** Если фича связана с отправкой ордеров или логированием — добавь её сюда.
3. **Оркестратор (`engulf_trader_bot.py`):** Свяжи новые вызовы.

### Фаза 3: Верификация
1. Запусти `uv run pytest`. Новый тест должен стать зелёным.
2. Запусти `uv run ruff check .` и `uv run basedpyright`.
3. Убедись, что старые тесты не сломались.

## 4. Выходные артефакты (Outputs)

- Новый тест в `tests/test_*.py`.
- Изменённый код в разрешённых файлах.

## 5. Ворота готовности (Definition of Done)

1. Новый тест зелёный.
2. Все старые тесты зелёные.
3. `ruff check` и `basedpyright` возвращают 0.
4. `git diff` не содержит изменений в запрещённых файлах (`config.py`, `.env`).

## 6. Стоп-условия и откат

- Если новая фича ломает старый контракт (например, меняет сигнатуру `calculating_signal`) — остановиться и доложить человеку.
- Если после 3 попыток тест не становится зелёным — откатить изменения (`git restore .`) и доложить.
- Если фича требует изменения 5 или более файлов — остановиться, написать краткий отчёт (какие файлы, почему так много) и **ждать прямого разрешения человека** на продолжение. Не начинать изменения без команды "Продолжай".
