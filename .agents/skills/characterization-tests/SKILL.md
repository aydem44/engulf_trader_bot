# Скилл: Защитный слепок поведения (characterization-tests)

## 1. Назначение и триггеры

- **Применять когда:** Нужно изменить логику в `main()` или `trader.py`, но текущее поведение не зафиксировано тестами.
- **НЕ применять:** Для нового кода (TDD) или если слепок уже снят и зеленый.

## 2. Предусловия (Inputs)

- Нет незакоммиченных изменений в рабочем коде (`git diff --exit-code` возвращает 0).
- `architecture-map.md` существует.
- Известна конкретная функция или блок кода, поведение которого нужно зафиксировать (например, блок проверки закрытия позиции).

## 3. Пошаговая процедура (Execution Steps)

### Фаза 1: Матрица сценариев
1. Выпиши 2-3 критических сценария (например: позиция закрылась по TP, позиция еще открыта, но старая запись closed-pnl существует).
2. Для каждого сценария определи входные данные (что вернет `get_positions`, что вернет `get_closed_pnl`).

### Фаза 2: Написание тестов с моками
1. Создай файл `tests/characterization/test_position_logic.py`.
2. Используй `unittest.mock.patch` для мокирования вызовов pybit (`session.get_positions`, `session.get_closed_pnl`).
3. Напиши тесты, которые вызывают функцию/цикл и проверяют ФАКТИЧЕСКОЕ поведение (даже если оно кажется багованным).
4. Убедись, что тесты не делают реальных HTTP-запросов к Bybit.

### Фаза 3: Запуск
1. Запусти `uv run pytest tests/characterization/ -q`.
2. Все тесты должны быть зелеными на текущем (нетронутом) коде.

## 4. Выходные артефакты (Outputs)

- Файл `tests/characterization/test_position_logic.py`.

## 5. Ворота готовности (Definition of Done)

1. `uv run pytest tests/characterization/ -q` возвращает 0.
2. В тестах нет реальных вызовов `session.get_positions` без мока.
3. В `git diff` нет изменений в `engulf_trader_bot.py` (код приложения не менялся).

## 6. Стоп-условия и откат

- Если для написания теста приходится менять код в `engulf_trader_bot.py` — остановиться. Тест должен подстраиваться под код, а не наоборот.
- Если тест падает на нетронутом коде — зафиксировать это как баг и доложить человеку.
