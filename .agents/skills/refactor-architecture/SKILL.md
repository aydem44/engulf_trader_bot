# Скилл: Безопасный рефакторинг архитектуры (refactor-architecture)

## 1. Назначение и триггеры

- **Применять когда:** `architecture-map.md` указывает на нарушение слоев (например, бизнес-логика в Data Provider, или прямые вызовы API в оркестраторе).
- **НЕ применять:** Для исправления багов (используй `fix-position-state`) или добавления новых фич (используй `add-feature`).

## 2. Предусловия (Inputs)

- Репозиторий проекта развернут в `~/projects/trading/engulf_trader_bot`.
- Рабочая ветка чиста (`git status --short` пуст).
- Все тесты зелёные (`uv run pytest`).
- `architecture-map.md` существует и содержит целевое видение слоев.

## 3. Пошаговая процедура (Execution Steps)

### Фаза 1: Фиксация исходного состояния
1. Запусти `uv run pytest -v`. Запиши, что все тесты проходят.
2. Составь план переноса: какие функции/классы переезжают из файла А в файл Б.
3. Убедись, что план не меняет сигнатуры публичных функций (или меняет их с обновлением всех вызовов).

### Фаза 2: Малые атомарные шаги
1. **Один шаг = один перенос.** (Например: "Перенести `calculating_signal` из `fetch_klines` в `strategy.py`").
2. После каждого шага запускай `uv run pytest`. Если тесты упали — немедленно откатывай (`git restore .`).
3. Не пытайся отрефакторить всё сразу. Если нужно переписать 3 файла, делай это в 3 отдельных шага.

### Фаза 3: Верификация поведения
1. Сравни логи (`bot.log`) или вывод функций до и после рефакторинга. Они должны быть идентичны.
2. Запусти `uv run ruff check .` и `uv run basedpyright`.

## 4. Выходные артефакты (Outputs)

- Изменённая структура кода (код переехал, поведение не изменилось).
- Обновлённый `architecture-map.md` (слои теперь соответствуют целевому видению).
- Все старые тесты зелёные.

## 5. Ворота готовности (Definition of Done)

1. `uv run pytest` возвращает 0 (все старые тесты прошли).
2. `ruff check` и `basedpyright` возвращают 0.
3. В `git diff` нет изменений в бизнес-логике (только перемещение кода и обновление импортов).

## 6. Стоп-условия и откат

- Если после переноса кода тесты покраснели и не чинятся за 2 попытки — откатить (`git restore .`) и доложить.
- Если рефакторинг требует изменения более 5 файлов — остановиться, написать отчёт и ждать прямого разрешения человека.
- Если для переноса нужно изменить внешний контракт (сигнатуру функции, которая используется в других местах) — остановиться и доложить человеку.
