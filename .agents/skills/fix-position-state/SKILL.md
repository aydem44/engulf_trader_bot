# Скилл: Исправление логики позиции (fix-position-state)

## 1. Назначение и триггеры

- **Применять когда:** В логах (`bot.log`) видны повторяющиеся открытия позиции, ложные закрытия или ошибки `IndexError` при вызове `get_positions()`.
- **НЕ применять:** Для добавления новых фич (для этого есть `add-feature`) или для изменения сигнальной логики.

## 2. Предусловия (Inputs)

- Репозиторий проекта развернут в `~/projects/trading/engulf_trader_bot`.
- Рабочая ветка чиста (`git status --short` не содержит незафиксированных изменений).
- В корне проекта существует файл `architecture-map.md` (если нет — создай его в Фазе 1).

## 3. Пошаговая процедура (Execution Steps)

### Фаза 1: Разведка структуры (Read-Only)
1. Просканировать дерево каталогов `engulf_trader_bot.py`, `strategy.py`, `trader.py`, `config.py`.
2. Найти все вызовы Bybit API (pybit) и понять, где они находятся.
3. Зафиксировать текущие слои: где логика, где API, где состояние позиции.

### Фаза 2: Построение карты архитектуры
1. Составить цепочку вызовов: `main() -> fetch_klines() -> strategy.py -> trader.py`.
2. Выписать все внешние контракты (Bybit, Telegram, CSV).
3. Определить зоны риска (где код может упасть или потерять деньги).

### Фаза 3: Определение зоны влияния правок
1. Сформировать список файлов, разрешенных к изменению (не более 3-5 файлов).
2. Зафиксировать список неприкосновенных модулей (например, `strategy.py` для задачи позиции).

## 4. Выходные артефакты (Outputs)

- Измененный код в разрешенных файлах (`engulf_trader_bot.py`, при необходимости `trader.py`).
- Обновленный `architecture-map.md` (если зона влияния была уточнена).
- Запись в `bot.log` о том, что ошибка устранена (при тестовом запуске).

## 5. Ворота готовности (Definition of Done)

1. Ошибка (R1, R2, R3 или R4) больше не воспроизводится при ручном тесте или запуске.
2. Все существующие тесты (`uv run pytest`) проходят успешно.
3. `ruff check` и `basedpyright` не выдают новых ошибок.
4. Запрещенные файлы (`strategy.py`, `config.py`) остались нетронутыми.

## 6. Стоп-условия и откат

- Если после 3 попыток исправить ошибку она все еще воспроизводится — остановиться, откатить изменения (`git restore .`) и доложить человеку.
- Если для исправления требуется изменить файлы за пределами разрешенной зоны — остановиться и доложить человеку.
- Если изменение ломает тесты стратегии (те, что мы написали) — немедленно откатить изменения.
